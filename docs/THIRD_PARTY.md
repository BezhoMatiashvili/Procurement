## 2. Copyleft and restrictive licences

### 2.0 What these licences ask of someone shipping the product

The tables below cite these by name. This is the reviewer's reading, not advice.

* **MPL-2.0**: File-level (weak) copyleft. Shipping the package unmodified inside a proprietary product is allowed: keep its licence text and notices with it. A changed MPL-covered file must be made available in source form, under the MPL, to whoever receives the product; the product's own files are not affected. Verify.
* **LGPL library**: Allowed in a proprietary product as a separate shared library that is dynamically linked. Ship the licence text and notices (they travel in the wheel's dist-info); do not prevent the recipient from replacing the library file with a modified build; make the library's source available (upstream's, unmodified: a link or written offer). Verify.
* **GCC runtime**: GPL-3.0-or-later with the GCC Runtime Library Exception: the exception lets a program that is not GPL use these runtime libraries, and no source of the product is owed for using them. Ship the licence text and notices. Verify.
* **LGPL-3.0 source**: LGPL-3.0 on plain Python source, vendored unmodified. Keep the licence text and notices; the recipient can replace the files because they are source. Verify.

## 7. How this file is made, and what it does not cover

* Licence precedence per package: `License-Expression`, then a short `License` field, then the `License ::` classifiers (`scripts/licences.py`). A name that leaves the variant open ("BSD", "Apache") is shown as such with no SPDX id.
* Every licence-looking file a package ships is scanned for titles and `License:` lines of copyleft licences. Code compiled into a wheel without a licence file (Rust and C dependencies of native extensions) is not enumerated; for those the package's own licence files are the only source, and `docs/sbom.cdx.json` lists the wheels' hashes.
* Packages are those of the lock for linux/x86_64 and Python 3.12.14; a different platform or architecture would need its own run.
* The Debian and Alpine packages inside the images are not enumerated here; `docker run --rm --entrypoint dpkg <image> -l` (or `apk info -vv`) on the built image does.
